# services/api

Private backend-for-frontend for the operator terminal.

The service exposes deterministic package snapshots and previews plus injected boundaries for preparing unsigned Solana Devnet transactions and observing a submitted Devnet signature. The default process has no execution ports, so preparation and observation fail with `EXECUTION_UNAVAILABLE`.

Preparation accepts only a normalized cash-and-carry request. The injected port owns route compilation and returns an unsigned materialization. The HTTP boundary independently verifies the Devnet identity, plan kind, trader signer, zero signatures, wire size, resolved-account count, compute-unit cap, lookup commitments, and evidence before returning `DEVNET_UNSIGNED_REVIEW_REQUIRED`.

Observation is read-only and reports `SUBMITTED`, `FINALIZED`, `FAILED`, or `EXPIRED`. The observation boundary has no signer, wallet authority, submission, simulation, broadcast, arbitrary instruction input, RPC URL input, or mainnet path.

Every terminal execution handoff is additionally protected by an injected Phase 8 readiness gate. The gate defaults to unavailable even when a venue runtime is configured. It recomputes the canonical readiness decision, requires `READY`, and requires one exact funded-operation manifest binding for environment, domain manifest, template manifest, settlement class, quote mode, size cohort, asset, operation and account commitments, action, principal, network fee, protocol fee, slippage, margin, recovery, loss, validity, runtime and configuration hashes, authority inventory, and complete categorized readiness evidence records. Canonical readiness evaluation also enforces aggregate asset and account budgets. The gate persists the exact funded-operation and readiness-decision hashes before releasing the handoff. Mainnet domains and environments are rejected unconditionally. Discovery, quoting, lifecycle reading, and other read-only evidence paths do not gain signing or write authority from this gate.

`FileExecutionReadinessPolicyProvider` consumes the canonical protocol-types `ReadinessDecisionInput` directly from an absolute external protocol-JSON file. It does not define another manifest format and reloads and validates the decision for every authorization. A trusted server-side scope resolver must independently derive the actual operation from durable attempt evidence. The browser cannot provide the scope. Durable gate evidence uses an external SQLite path. Until the policy provider, scope resolver, gate, and evidence store are all explicitly composed, local, Devnet, Base Sepolia, Arbitrum Sepolia, and Hyperliquid Testnet handoffs remain unavailable.

The service also exposes an internal unsigned-order boundary at POST `/internal/terminal/orders` and GET `/internal/terminal/orders/{orderHash}`. The browser request carries only `contextId`, `owner`, `settlementAccount`, `size`, `slippageBps`, and `idempotencyKey`; size is parsed to integer atoms with the server-owned active context base-asset decimals and the authoritative clock is injected by the server. Orders are stored as `UNSIGNED_CREATED` and responses state that trader authorization and solver quoting are still required. The default process has no order ports, so both routes fail with `ORDER_CREATION_UNAVAILABLE`. This boundary performs no signing, quote creation, transaction preparation, submission, simulation, broadcast, or mainnet path.

It binds to loopback by default. Cross-origin browser access is allowed only for the exact configured terminal origin.

Concrete Devnet ports are built by `createSolanaDevnetExecutionPorts`. The factory must receive reviewed server-owned contexts and a trusted Devnet RPC before the existing server can use it.

The Solana Devnet runtime is disabled by default. Enabling it requires an absolute `NARYX_SOLANA_DEVNET_RUNTIME_MANIFEST` path to an external immutable protocol-JSON manifest in `ACTIVE` state, a signerless `NARYX_SOLANA_DEVNET_RPC_URL`, a durable preparation database outside the checkout, and a loopback read-only binding source. Startup verifies the Devnet genesis and the exact core, reservation, package-book, perpetual-adapter, and perpetual-venue program and ProgramData identities. Each preparation resolves only a durable selected attempt, canonical order, and signed quote, then validates domain, registry, resource, series, reservation, lookup-table, compute-unit, address-count, packet-size, and postcondition bindings before returning an unsigned zero-signature transaction.

The loopback binding source must materialize current finalized account evidence. The API validates that evidence against the reviewed deployment and the adapter compiler, but it does not submit, simulate, sign, airdrop, deploy, initialize, or independently attest the upstream source. The browser remains the only eventual Devnet transaction sender after human review. A stale or mismatched binding, wrong genesis, changed program identity, missing durable evidence, or unsupported configuration fails closed. There is no mainnet or default-wallet fallback.

The Base Sepolia atomic boundary is disabled by default. When enabled, `NARYX_BASE_SEPOLIA_RUNTIME_MANIFEST` must name an external immutable protocol-JSON manifest containing the exact reviewed deployment, domain, admission, execution-bound, finality, and `ACTIVE` activation identities. `NARYX_BASE_SEPOLIA_RPC_URL` supplies a signerless read endpoint. Startup verifies chain ID and every deployment bytecode hash, and each attempt rechecks them before materializing durable selected order and quote evidence. Missing, inactive, stale, or mismatched identity fails the boundary closed. The API has no wallet, signing, submission, or broadcast path.

The Arbitrum Sepolia asynchronous boundary is also disabled by default. When enabled, `NARYX_ARBITRUM_SEPOLIA_RUNTIME_MANIFEST` must name an explicit absolute external path to an immutable protocol-JSON manifest with `ACTIVE` state, the reviewed domain and deployment identities, exact GMX dependencies, route and series constraints, finality and evidence requirements, and the deployment observation start block. `NARYX_ARBITRUM_SEPOLIA_RPC_URL` supplies a signerless viem public client. Startup and every observation verify chain ID, deployed bytecode hashes, coordinator admission, isolated-account controller, adapter account binding, and execution-class identity. Attempt evidence is discovered from coordinator transition and request-registration logs at or after the immutable deployment block and accepted only when live coordinator terms match the durable order, quote, route, series, execution-class, and evidence-schema hashes exactly.

This runtime exposes only the existing asynchronous observation path. It can report coordinator, entry-adapter, recovery, conflict, and finalized exit evidence that already exists onchain. It cannot reserve a package, create a GMX request, fund execution, recover or exit a position, sign, submit, simulate, or broadcast. Missing logs, duplicate package matches, incomplete evidence, wrong-chain RPCs, altered code, and configuration mismatches fail closed.

The service also exposes POST `/internal/terminal/hyperliquid-testnet/execute`. The browser request carries only `attemptId` and `idempotencyKey`. The server-owned injected port owns the Testnet attempt and returns a sanitized `hypercore:testnet` `TESTNET` result. The default process has no port, so the route fails with `EXECUTION_UNAVAILABLE`. The current limit is one identified attempt per request with no plan, account, signer, or venue payload from the browser.

Hyperliquid Testnet is disabled unless `NARYX_HYPERLIQUID_TESTNET_RUNTIME_ENABLED=true`. Evidence preparation and executor submission have additional independent gates, `NARYX_HYPERLIQUID_TESTNET_EVIDENCE_ENABLED` and `NARYX_HYPERLIQUID_TESTNET_EXECUTOR_CLIENT_ENABLED`, which also default to false. Readiness is available only when both are enabled and correctly composed. The environment must be exactly `TESTNET`. The external runtime config must be strict protocol JSON with version 1 and the exact `hypercore:testnet` domain manifest, solver, series, execution class, market, and evidence-bound identities. Its optional `orderContext` enables canonical Testnet cash-and-carry order creation and binds the owner and settlement account to the configured dedicated trading account. The context carries exact quantity, price, fee, margin, residual, recovery, and expiry bounds. Without `orderContext`, Hyperliquid order creation remains unavailable. The evidence and executor origins must be separate loopback HTTP origins. The execution journal must use an absolute durable path outside the repository.

The private solver handoff is GET `/internal/solver/hyperliquid-testnet/attempts/{attemptId}`. It is loopback-only and returns protocol JSON with exactly `{ "version": 1, "attempt": ... }`, where `attempt` is the canonical handoff produced from durable selected order and quote evidence. The executor client posts only `attemptId` and `idempotencyKey` to the separate solver executor process, applies a bounded timeout and response size, and validates the exact Testnet result before durable storage. The API never loads a Hyperliquid signer and has no direct exchange transport or network write authority.

`SqlitePackageExchangeStore` persists the package exchange. Economic strategy series, series execution classes, and package matching policies are stored as canonical bytes plus protocol JSON under their canonical hashes. A published identity and version can never be re-registered with different content, and an execution class is accepted only when its series and a matching policy written for the same class are already registered. Each execution class has one package book. Every submission, implied-liquidity admission, source-version observation, amendment, cancellation, and halt runs the protocol-types matcher inside one immediate SQLite transaction. Allocations are append-only and replay by taker order id. Consumed source reservations are append-only under a global primary key, so a reservation is single-use across every book, and source versions only move forward so stale implied liquidity cannot return. Loaded documents, book state, and allocations are revalidated against their canonical hashes and policy and fail closed as `CORRUPT_ROW`. `allocationTape` pages a book's allocations in recorded order after an opaque cursor.

`createPublicMarketRequestHandler` serves read-only public market data over the exchange store and returns false for any other path, so a host server can compose it. `GET /v1/market/books/{executionClassId}` returns live depth per price level with direct and implied quantity kept apart. `GET /v1/market/books/{executionClassId}/tape?after=&limit=` returns trades with price, quantity, maker source, and allocation hash, and omits participant, common-control, taker order, and source-reservation identities. `GET /v1/market/allocations/{takerOrderId}` returns full allocation evidence and its matching policy; possession of the taker order id is the read capability, and the tape never lists it. Query parameters are whitelisted, writes are refused with 405, and requests are rate limited per client window. The handler holds no signer and is not mounted in the private terminal server; hosting it requires an exchange store configured with the supported series semantics.

It may depend on `packages/protocol-types`, `packages/adapter-core`, `packages/adapters/*`, and `deployments`. It must not depend on `apps/web`, `packages/sdk`, or another service's internals.

The Hyperliquid Testnet evidence runtime is separate from execution. It resolves an attempt only from the durable selected intent, canonical order, and signed quote stores, verifies the exact domain, solver, route, market metadata, bounds, and expiry, and can call only loopback solver preparation and reconciliation endpoints. The executor client is independently gated and owns no signer. Neither partial runtime is reported ready by itself.
