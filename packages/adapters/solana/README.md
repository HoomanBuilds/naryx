# Solana conformance adapter

This package compiles an admitted atomic cash-and-carry package into an authenticated conformance execution plan. It resolves account addresses from named route bindings, derives the config, solver registry, receipt, and nonce-marker PDAs, computes the core execution digest, and places its Ed25519 verification instruction immediately before `execute_conformance_atomic`. It uses the published Anchor IDLs in `deployments/solana/conformance/idl` for instruction and receipt encoding.

`compile` obtains the 64-byte execution signature through the configured signature provider. `compileAuthenticated` accepts a signature produced outside the adapter. `simulate` verifies the RPC genesis hash and submits only an unsigned simulation. `readEvidence` reads a receipt PDA and verifies the program owner, domain, order hashes, trader, solver, nonce, action, and quantity. This package has no private-key storage or broadcast path.

`qualifySolanaMainnetShadow` is a separate signerless production-state evidence boundary. It requires an explicit HTTPS RPC endpoint, verifies the mainnet-beta genesis hash from chain data, reads one finalized account batch, and checks exact upgradeable program identity, deployment slot, authority, executable state, account owner, data length, optional expected data hash, SPL mint decimals, and mint and freeze authorities. Venue and market accounts are named and typed by the caller instead of being discovered permissively.

The returned record contains only the endpoint, finalized slots, public identities, lengths, authorities, balances, and SHA-256 commitments. It has no raw account bytes, signer, simulation, transaction construction, or broadcast method. Persisted output is point-in-time `READ_ONLY_SHADOW` evidence for review against an immutable manifest. It is not runtime configuration, activation evidence, a deployment record, or authorization for a mainnet write. A coherent production-state clone must separately retain the raw account bytes at its pinned snapshot boundary.

`qualifySolanaDeploymentAuthority` is a separate signerless activation gate over explicit observed evidence. It checks exact program and derived ProgramData linkage, loader ownership, executable state, deployed code hash, upgrade authority and immutability policy, domain authorities, forbidden role collisions, and lifecycle caps. Entry-paused and exit-only resources must retain positive exit capacity. The injected evidence port has no transaction construction, signer, or write method, and the result is not a runtime snapshot.

The caller must pass the result of `validatePackageAdmission`. The conformance program authenticates the exact execution digest with the solver named by the Ed25519 verification instruction, which must be in the registry's active solver set (additions wait out the configuration delay; the pauser removes a solver at once), and enforces nonce replay protection, exact spot and short quantity changes, and the stated spot and collateral limits. It does not reconstruct the complete package admission or collect fees onchain. This adapter is for local and test networks until those checks exist in a production verifier.
